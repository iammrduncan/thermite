## 1. Living Requirements & User-Stories Capture System

Thermite v1 **replaces v0.x's 272-file `.goal` graveyard** with one living ledger tightly wired into [`process.md`](process.md):

- **GitHub Issue = raw intake:** bug report, field friction, contributor PR, or owner request.
- **`REQ-NNN` in this file = durable product contract:** persona, user story, verifiable cross-surface acceptance criteria, wave (`v1.0` / `v1.1` / `v1.2` / `v1.3` / `dropped`), Goal mapping (`Goal 1`–`14`), and current lifecycle status.
- **Phase doc (`docs/plan/v1/phases/<slug>.md`) = temporary build brief:** cites its `REQ-NNN` entries at **Gate 1**, locks scope & mockups at **Gate 5**, and marks `REQ-NNN` as `Verified` at **Gate 6** before moving to `phases/_completed/`.

### 1.1 Capture, Triage & Parity Rules

1. **No speculative REQs (Gate 1):** every new `REQ-NNN` must cite a public GitHub issue/PR number or concrete reproduced usage evidence. Pure `Fix` bugs and refactors stay in GitHub issues/PRs without minting a new REQ; `Change` tweaks cite an existing `REQ-NNN`.
2. **One-Surface Parity by default (Gate 3):** every operator-facing `REQ-NNN` specifies verifiable acceptance criteria through the single `core/api` `ActionDef` registry (or `PluginApi.registerActions`) — covering REST, policy-filtered MCP, CLI (`--json`), and UI with zero surface orphans.
3. **Plugin-first disposition:** default new post-MVP capabilities to optional plugins (`v1.1`–`v1.3` or external packs) rather than expanding `v1.0` Core (`~12.0k–16.2k LOC`).
4. **Never renumber or delete IDs:** mark retired entries `Dropped` (referencing `DROP-NN` or the superseding `REQ-NNN`) so commits, tests, issues, and completed phase docs keep permanent traceability.

### 1.2 Lifecycle States & Process Hooks

| Status | Meaning | Trigger in [`process.md`](process.md) |
| --- | --- | --- |
| `Proposed` | Real evidence captured; unscheduled or awaiting clarification/benchmark | Created at Gate 1 intake from GitHub issue/PR or field pain |
| `Accepted` | Slotted into a release wave (`v1.0`–`v1.3`) and Goal (`Goal 1`–`14`) | Locked by owner decision (`decisions.md` or Gate 5 sign-off) |
| `Verified` | Shipped, tested across surfaces, docs updated, owner human checks passed | Updated in the same commit as Gate 6 phase close-out |
| `Dropped` | Intentionally rejected or replaced by an anti-requirement (`DROP-NN`) | Owner call recorded in §3 with concrete rationale |

### 1.3 Copyable Intake Template (New `REQ-NNN` Row)

```markdown
| `REQ-NNN` | `v1.x` · `Goal N` · `Proposed` | As a **<Persona>**, I want <capability>, so that <measurable outcome>. | **Accept:** <verifiable behavior>. **Parity:** `core/api` `<action>` (REST/MCP/CLI/UI) + test. | `#<issue>` / `PR #<pr>` |
```

## 3. Explicitly Dropped / Anti-Requirements (What v1 Intentionally Kills)

Any proposal, phase doc, or PR attempting to reintroduce these v0.x patterns is rejected automatically under [`process.md`](process.md) §4.

| ID | Dropped v0.x Pattern | Why It Failed (Evidence) | v1 Replacement |
| --- | --- | --- | --- |
| `DROP-01` | **`rig` abstraction & per-rig supervisors/ledgers** | Split state across rig SQLite ledgers, 6 NATS streams, and rig-tied models/campaigns; blocked sharing GPUs across runs (Goals `206`, `258`, `276`). | Run owns its agents & compute share; shared `machine › device` pool with thin hardware-only runners. |
| `DROP-02` | **Hardcoded `OWNER_ONLY_KINDS` walls (28 kinds)** | Blocked delegated operator agents from promoting, closing, invalidating, or adjusting limits, forcing manual human relay loops (`sansio-nats-contract.md` §4). | Composable `PolicyGrant` profiles (`autonomous_delegate` grants 100% campaign ops); only internal run workers/advisors stay walled. |
| `DROP-03` | **Synchronous SQLite word-index KB (11.6k LOC)** | Froze Control's event loop for 2–5 min, triggered OOM heap crashes (`#84`) and liveness SIGKILLs (`#113` #11), with 4× text duplication. | Lean async PostgreSQL 18 FTS + `pg_trgm` Core (`<= 1,100 LOC`) + optional `knowledge-semantic` (`pgvector`) plugin. |
| `DROP-04` | **Giant tarball exports & manual `.patch` shuffling** | 621 MB / 15,671-file exports timed out under per-file git commits (`#89`); champions stranded in unapplied `.patch` files (`#39`). | First-class `git-sync` (`push \| pr \| tag \| none`) + fast incremental `thermite pull <run>` from Control's bare mirror. |
| `DROP-05` | **Separate multi-agent folder-sync `live` deployment** | Fragile external sync choreography to mirror runs onto `live.usethermite.com` (`README.md` §5). | Per-run `live` toggle projecting sanitized `t.live.<run>.>` events to `live-publish` / `thermite live`. |
| `DROP-06` | **UI-only / API-only / MCP-only surface splits** | 42/90 dashboard form routes had no REST API; "Needs you" existed only as HTML; forms drifted from server schemas (`#68`, `ui-refresh-guide.md` §3). | Single `core/api` `ActionDef` registry auto-generating REST, policy-filtered MCP, typed client, CLI, and docs. |
| `DROP-07` | **Fail-on-shrink check ratchets & regex CSS bans** | `size-baseline.json` `--lower`, `loose-ends.json`, and `design-system.test.ts` `className=` bans burned massive agent tokens on file-split churn (`onboarding-and-mvp.md` §4). | `< 2 min` checks (`tsc`, Biome, `public.mjs`, Sans-I/O + PGlite tests) + package `exports` boundaries. |
| `DROP-08` | **Hidden default research turn/trial/spend caps** | Silently cut off productive runs or imposed arbitrary `max_open_attempts = 4` stalls (`#113` #3, Goals `003`, `230`). | Zero default research caps; only explicit user budgets and deterministic safety circuit breakers. |
| `DROP-09` | **Double/triple confirmation ceremony on routine close** | Operators explicitly demanded killing multi-step confirmation hoops to close a run (`#76`). | Clear 1-step close/pause actions with undo/audit trail; typed confirm reserved strictly for destructive data deletion. |
| `DROP-10` | **Container-only wall dogma blocking native Apple Silicon** | Forced macOS Metal/MLX into a Linux VM + Vulkan bridge at ~76% speed while breaking MLX entirely (`#87`, `#93`, Goal `279`). | Pluggable `WallPlugin` (`wall-tools`, `wall-os`, `wall-microsandbox`, `wall-container`) + native macOS `launchd` + `device-metal` day one. |
